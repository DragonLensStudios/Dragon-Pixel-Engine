# S1.0 Architecture Bootstrap and Core Editor Evidence

> **Evidence status:** Local Slice 1 implementation passed on Windows and Ubuntu; macOS acceptance pending
> **Recorded:** 2026-07-24
> **Architecture baseline:** `DPE-ARCH-0005`
> **Milestone scope:** S1.0 bootstrap plus the Slice 1 Windows/Ubuntu core editor/runtime vertical slice

## Outcome

Dragon Pixel Engine now has buildable and testable Windows and Ubuntu Slice 1 implementations for the portable core, managed boundary, framework workers, initial external Python boundary, canonical project lifecycle, and Qt editor. Both platform matrices pass in Release and their native AddressSanitizer configurations.

This is not Slice 1 completion evidence. The same source, sample, and tests must still execute on macOS 14+ arm64. KNI remains experimental until the full three-platform conformance matrix passes.

## Implemented production foundation

- C++20/CMake modules for core identity and diagnostics, scenes/entities/components, metadata, command validation, deterministic serialization, and `dpe_api_v1`.
- UUID-backed world, scene, entity, hierarchy, enabled state, UUID component identities, diagnostic qualified names, and versioned component records.
- Deterministic UTF-8 scene format version 2, version 1 migration, unknown/newer opaque preservation, atomic replacement, backup, and recovery.
- Validated commands plus all-or-nothing transactions with rollback when any command fails.
- A versioned C ABI with opaque handles, fixed-width values, explicit UTF-8 buffers, allocator pairing, status codes, capabilities, and contained exceptions.
- `DragonPixel.Contracts` targeting `.NET Standard 2.1`, with .NET 10 interop, runtime worker, adapter host, MonoGame worker, and experimental KNI worker.
- A shared component metadata schema consumed by native registration and a real C# incremental source generator.
- Versioned, length-prefixed JSON-RPC control with request IDs, negotiated capabilities, structured errors, cancellation, diagnostics, and per-session capability tokens.
- Named-pipe transport passing on Windows and Unix-domain-socket transport passing on Ubuntu, with macOS execution pending.
- Versioned BGRA8 shared-memory frame transport with seqlock coordination.
- A user-restricted editor automation broker and dependency-free Python client for negotiation, inspection, dry-run, validated mutation, rejection, cancellation, and token-redacted JSONL audit.
- A deterministic Slice 1 sample containing a camera, 2D sprite, 3D cube mesh/material, native and managed components, a light, and an intentionally missing component.

## Implemented editor vertical slice

The Qt 6.11 Widgets editor includes:

- A `QMainWindow` shell with Scene, Hierarchy, Project/Assets, Inspector, and Console docks.
- A render-capable authoring viewport showing the sample's 2D sprite and animated 3D cube.
- Canonical project and scene open, root-containment validation, deterministic atomic save, full close/reopen, asset rediscovery, hierarchy selection/rename/enabled state, entity creation/reparenting, component add/remove/enabled state, and property editing.
- A metadata-driven Inspector that does not load arbitrary game code and presents opaque component payloads read-only.
- Command/transaction-routed authoritative mutations with hierarchy-cycle, atomic rollback, and opaque-edit validation.
- Distinct preview and play workers for MonoGame/KNI, with process-ID proof, pause, resume, stop, forced play-worker crash, diagnostics, and automatic isolated restart controls.
- Immutable temporary play snapshots. Stop disposes the worker world and does not write runtime state to the saved scene.
- Accessibility names for the shell, viewport, panels, and primary controls.

- Run representative real MonoGame/KNI projects through the read-only scanner.
- Complete the final multi-platform Qt artifact inventory, notices/source-offer/relinking materials, and pre-distribution legal review. The Windows development inventory is recorded in `Compliance/Qt 6.11.1 LGPL Deployment Inventory.md`; neither document is legal advice.

## Decision

The Windows development environment and the Windows/Ubuntu Slice 1 implementation paths are ready for iterative editor work and repeatable local testing. The architecture's cross-platform support promise remains unchanged, and Slice 1 remains in progress until macOS evidence is recorded.

```powershell

$vsPath = & $vswhere -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
& (Join-Path $vsPath 'Common7\Tools\Launch-VsDevShell.ps1') -Arch amd64 -HostArch amd64
cmake --build --preset windows-release --target DragonPixelEditor
.\scripts\dev\Launch-Editor.ps1 -SkipBuild
```

During this check, the all-target build stopped while relinking the separate `dpe_physics_tests.exe` target without an emitted linker diagnostic. This launch check therefore does not supersede the recorded full-matrix evidence or constitute a fresh full test pass.
